一台 VPS，无限 HTTPS 站点

加站点只用一行命令。Cloudflare DNS 记录、Let's Encrypt 证书签发与续签、反向代理配置，全自动。

你有公网 IP、有域名托管在 Cloudflare、想在上面跑一堆服务 —— 这套方案把「配 DNS、申请证书、配反代、忘记续签」这四件破事一次性解决掉。

自动 HTTPS 自动续签 Cloudflare API DNS-01 / 泛域名 零 pip 依赖 不绑定 Docker MIT
一键部署 手动两步 加站点 
# 在你自己的电脑上，不是服务器上
cd domain-autopilot
bash deploy.sh root@你的IP -p 22

# 部署脚本会做：本地文件检查 → 远程预检 → 上传 → 安装
# 装完用这条命令开面板隧道
ssh -N -L 8848:127.0.0.1:8848 root@你的IP
# 上传整个目录（tar 管道，一次连接搞定）
tar czf - -C domain-autopilot --exclude=__pycache__ . \
  | ssh root@你的IP 'mkdir -p /root/domain-autopilot && tar xzf - -C /root/domain-autopilot'

# 安装
ssh -t root@你的IP 'cd /root/domain-autopilot && bash setup.sh'
# 一行加站点：DNS 记录 + 证书 + 反代 + 热加载
add-site.sh app.example.com 127.0.0.1:8080

# 上游可以是本机端口、局域网 IP、Docker 服务名
add-site.sh nas.example.com  192.168.1.10:5000
add-site.sh wiki.example.com wiki:3000

# 20 秒后验证
curl -sI https://app.example.com | head -1

Token 只需粘一次，落到 /etc/caddy/cf.env（600 权限），Caddy、脚本、面板三方共用。

01流量怎么走

外部只暴露 443。证书由 Caddy 用 DNS-01 向 Let's Encrypt 申请，DNS 记录由 Caddy 直接调 Cloudflare 维护 —— 全程没有手写 API 调用。

02能做什么

六个特性，每个都对应一件原本要手动干的活。

自动 HTTPS

证书由 Caddy 自己向 Let's Encrypt 申请，到期前自动续，没有 certbot，没有 crontab。

DNS 自动建/删

加站点时立即调 Cloudflare API 建记录；删站点连带删干净，不留孤儿记录。

IP 漂移自愈

VPS 换公网 IP 后 A 记录自动更正，另有每日巡检兜底比对。

泛域名证书

一张 *.example.com 管所有子域，以后加子域不用重新申请。

上游不限形态

本机端口、局域网另一台机器、Docker compose 服务名都能当上游。后端若是自签 HTTPS 的面板（x-ui / 3x-ui 等），直接写地址栏那串也行：路径会被自动剥掉， https:// 自动补上，证书校验自动跳过。

Web 管理面板

纯标准库后端 + 单文件前端，站点增删、证书到期、DNS 状态一屏可见。

面板默认本地监听

面板只听 127.0.0.1:8848，请务必不要改成 0.0.0.0 —— 它能增删站点还能读 Token。

SSH 端口自动放行

改过 SSH 端口也不怕，安装脚本先推断真实端口再配防火墙 —— 这个坑会真的把你锁在门外。

幂等可重跑

所有脚本重复执行都不产生副作用，配置注入前先 grep 判断。

03为什么不直接用现成项目

生态里 Traefik 64.3k★、Caddy 引擎 74.6k★、nginx-proxy-manager 34.1k★ 都很成熟。但把它们源码过一遍会发现：没有任何一个原生做到「自动建 Cloudflare DNS 记录 + 反代 + 自动续签」一条龙 —— DNS 那一步都得自己补。

项目star自动建 CF DNS自动证书是否绑 Docker
caddyserver/caddy74.6k需 dynamic_dns 插件是否
traefik/traefik64.3k否是强绑定
jc21/nginx-proxy-manager34.1k否是强绑定
caddy-docker-proxy4.6k否是强绑定
本项目—是（API 直接调用 + 幂等）是否

如果你的服务全部跑在 Docker 里、而且加得很频繁，老实说直接用 caddy-docker-proxy 更好，别在这套脚本上浪费时间。这套方案的价值在于「项目是散的」。

04文件清单

九个文件，职责单一，可以按需要挑着用。

文件在哪执行作用
deploy.sh你的电脑预检 + 上传 + 远程安装，一条命令装完整个栈
setup.sh服务器装依赖、防火墙、Token、脚本、cron、面板
enable-cf-native.sh服务器打开 Caddy 原生 CF 集成（DNS-01 + dynamic_dns）
cf.sh服务器Cloudflare API 封装，可被 source 也可单独调试
add-site.sh服务器加/删站点：DNS + 配置 + 证书，一行搞定
sync-dns.sh服务器每日巡检：IP 漂移、记录对齐、证书到期预警
admin-api.py服务器面板后端，纯标准库，默认听 127.0.0.1:8848
admin-ui.html浏览器面板前端，单文件，无构建
Caddyfile服务器主配置，站点配置靠 import 加载

05上线前请确认

这些都是「出了事才发现没做」的项。

云服务器安全组

  • 控制台里也要放行 443，只配系统防火墙没用
  • 80 端口跑 DNS-01 后可直接关闭
  • 8848 永远不要对公网放行

SSH 与身份

  • 改默认端口，PermitRootLogin prohibit-password
  • 禁用密码登录，只用密钥
  • 确认 ufw status 里有你的 SSH 端口

管理后台别裸奔

  • Portainer / NAS 后台不要直接挂公网
  • 走 Tailscale，或给站点加 basicauth
  • 定期 tar czf /root/caddy-backup.tar.gz /etc/caddy

06命令速查

日常 排错 
add-site.sh app.example.com 127.0.0.1:8080   # 加站点
add-site.sh -r app.example.com               # 删站点 + 删 DNS 记录
add-site.sh example.com 127.0.0.1:8080 -d    # 强制 DNS-01
sync-dns.sh --check                          # 只看报告不动手

bash /usr/local/lib/caddy/cf.sh check        # Token 连通性
bash /usr/local/lib/caddy/cf.sh ip           # 本机公网 IP
bash /usr/local/lib/caddy/cf.sh resolve app.example.com
journalctl -u caddy -n 50 --no-pager          # Caddy 日志
journalctl -u admin-api -n 50 --no-pager     # 面板日志
caddy validate --config /etc/caddy/Caddyfile # 配置校验
caddy list-modules | grep -E 'cloudflare|dynamic_dns'
systemctl status caddy admin-api --no-pager

注意：开启 Cloudflare 橙色云代理后，浏览器看到的是 Cloudflare 的证书而不是 Let's Encrypt 的 —— 这是正常的，不是配错了。
